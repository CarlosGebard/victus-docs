# Victus Contracts

Contracts define stable and explicit system boundaries across the Victus ecosystem.

Contracts exist to reduce ambiguity between:

- repositories
- pipelines
- services
- infrastructure
- AI agents
- humans

## Contract Principles

Victus prioritizes:

- deterministic systems
- explicit interfaces
- traceable reasoning
- modular ownership
- low hidden context
- reproducible behavior

## Ecosystem Contracts

- [Repository Documentation Contract](repository-documentation-contract.md)
- [Artifact Contract Hub](artifacts.md)
- Event Contracts
- Claims Schema Contracts
- Storage Layout Contracts
- API Boundary Contracts

## Rules

Contracts should:

- describe stable expectations
- avoid implementation-specific details
- evolve carefully
- expose ownership clearly
- remain machine-readable
- be referenced by architecture documents

Implementation details belong inside repository-local documentation.
